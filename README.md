# 🎾 테니스 취소 알림 (여러 지역 확장 가능)

여러 지역의 테니스장 예약 사이트를 한 앱에서 감시할 수 있도록 만든 웹앱입니다.
예약 취소로 빈자리가 생기면 브라우저 푸시 알림으로 바로 알려줍니다.

현재 지원하는 사이트:
- **고양특례시테니스협회 (gytennis.or.kr)** — 검증 완료
- **도봉구시설관리공단 (다락원체육공원 테니스, yeyak.dobongsiseol.or.kr)** — ⚠️ 베타
- **김포시체육회 (파르코스 테니스장, gimposports.or.kr)** — ⚠️ 베타, 아래 참고

## 구조

- `server.js` — Express API 서버 + 정적 파일 서빙 (로컬 실행 + Netlify Function 재사용 겸용)
- `providers/` — **사이트별 스크래퍼**. 사이트마다 파일 하나씩 (예: `providers/gytennis.js`)
  - `providers/index.js` — 모든 프로바이더를 등록하는 레지스트리
  - `providers/_template.js` — 새 지역 추가할 때 복사해서 쓰는 템플릿
- `scheduler.js` — N분마다 감시 대상들을 확인 (프로바이더에 상관없이 동일한 방식으로 동작)
- `push.js` — 웹 푸시(Web Push) 발송 (특정 기기들에게만 보냄)
- `store.js` — 저장소 선택자 (로컬은 파일, Netlify는 Blobs)
  - `storage/fileBackend.js` — 로컬 JSON 파일 저장 (`data/` 폴더)
  - `storage/blobsBackend.js` — Netlify Blobs 저장
- `netlify/functions/` — Netlify 배포용 서버리스 함수 (`api.js`, `tick.js`)
- `public/` — 프론트엔드 (사이트 선택 → 코트 선택 → 날짜 선택 구조)

## 👥 다중 사용자 구조 (target / interest / subscription)

여러 사람이 같은 코트를 감시해도 사이트에 중복으로 요청이 나가지 않도록,
"확인할 대상"과 "누가 관심있는지"를 분리했습니다.

- **target** — 확인할 대상 (예: "고양 대화코트 이번 달 전체"). `provider+grp+mode+date`
  조합이 같으면 몇 명이 등록하든 target은 딱 하나만 존재해요.
- **interest** — 어떤 기기(deviceId)가 어떤 target에 관심있는지 연결하는 정보.
  같은 target이라도 여러 기기가 각자 interest를 가질 수 있어요.
- **subscription** — 브라우저 푸시 구독 정보. deviceId에 연결됩니다.

**동작 흐름**: 스케줄러는 target 단위로 딱 한 번만 확인 → 변화가 생기면 그 target의
interest들을 찾아서 → 그 deviceId들의 subscription에만 알림을 보냄.

**deviceId는 어떻게 만들어지나요?**: 로그인 없이도 기기를 구분할 수 있도록,
브라우저가 처음 접속할 때 무작위 ID를 만들어서 `localStorage`에 저장해두고 계속
재사용합니다 (`public/app.js`의 `getDeviceId()`). 브라우저 데이터를 지우면 새 기기로
인식되어 감시 목록이 초기화돼요 (알림 구독도 다시 해야 함).

**한 target에 아무도 관심이 없어지면**: 마지막 interest가 삭제되는 순간 그 target도
자동으로 함께 삭제되어, 스케줄러가 더 이상 그 코트를 확인하지 않게 됩니다.

## 고양특례시테니스협회는 어떻게 동작하나요?

`https://www.gytennis.or.kr/daily/{grp}/{date}` 일별 상세 페이지를 파싱해서
**코트별 x 06:00~22:00 2시간 단위 시간대별로 예약 가능 여부**를 정확히 읽어옵니다.

- 슬롯 안에 빈 표시(`public-empty-slot`)만 있으면 → 예약 가능
- 사람 이름/단체명이 표시되어 있으면(개인 예약, 단체 대관 모두 포함) → 예약됨

또한 `/daily/{grp}` 페이지의 `#ensdat` hidden input에는 그 달 날짜별
"예약 가능 슬롯 총 개수"가 이미 들어있어서, "전체 코트 · 이번 달 전체 감시"
모드에서는 이 값으로 가볍게 스캔하다가 늘어난 날짜만 상세 조회합니다.

별도의 헤드리스 브라우저(Playwright 등) 없이 단순 HTTP 요청 + HTML 파싱만으로 동작해요.

## 도봉구시설관리공단은 어떻게 동작하나요? (⚠️ 베타)

다락원체육공원 테니스장(코트 1~9면)을 대상으로 합니다. 이 사이트는 고양시와 구조가 달라서:

- **월별 캘린더**: 날짜마다 "예약가능/예약마감/휴장일/예약종료" 같은 상태 텍스트만 있고
  (고양시처럼 정확한 빈자리 "개수"가 아님), 이걸로는 코트 9면 중 하나가 예약/취소돼도
  캘린더 상태 자체가 거의 안 바뀝니다 (다른 8면이 여전히 열려있으니까요).
- 그래서 도봉구는 **"이번 달 전체 감시"를 선택해도, 매 확인 주기마다 남은 날짜들의
  실제 시간대별 상세표를 다 직접 비교**합니다 (고양시처럼 "총 개수가 늘었을 때만"
  들여다보는 가벼운 방식이 아니라, 매번 정확하게 확인하는 방식). 그만큼 요청이
  좀 더 나가지만(이번 달 남은 날짜 수만큼, 3분마다), 개별 코트 예약 취소도 정확히 잡아냅니다.
- **일별 상세**: 코트 1~9번 x 1시간 단위 시간표가 있고, 체크박스에 `disabled` 속성이
  있으면 마감, 없으면 가능으로 판단합니다. → **아직 실제로 "예약가능"한 날짜의 페이지를
  확보하지 못해서, 이 부분은 합리적 추정으로 작성했고 라이브 검증이 필요해요.**

배포하신 뒤에 "예약가능"으로 뜨는 날짜를 하나 감시 등록해보시고, 만약 상세 시간표가
이상하게 나오면(예: 전부 마감으로만 나온다거나) 그 날짜 페이지를 Ctrl+S로 저장해서
다시 보내주세요. `providers/dobong.js`의 `fetchDayDetail` 부분만 수정하면 됩니다.

## 설치 및 실행

```bash
npm install

# VAPID 키 생성 (웹 푸시에 필요)
npx web-push generate-vapid-keys
```

`.env.example`을 복사해 `.env`를 만들고, 위에서 생성된 키를 넣어주세요.

```bash
cp .env.example .env
```

서버 실행:

```bash
npm start
```

브라우저에서 `http://localhost:3000` 접속 후:
1. "이 브라우저에서 알림 받기" 클릭 → 알림 권한 허용
2. **사이트를 선택**하고, 전체 코트를 통째로 감시하려면 "전체 코트 · 이번 달 전체 감시 시작" 클릭
3. 특정 코트+날짜만 정밀하게(시간대까지) 보고 싶으면 사이트/코트/날짜 선택 후 등록

## 감시 모드 2가지

| 모드 | 동작 방식 | 언제 쓰나요 |
|---|---|---|
| **월 전체 (자동)** | 코트당 1번의 요청으로 이번 달 전체 날짜의 "빈자리 총 개수"만 가볍게 확인. 빈자리가 늘어난 날짜가 있으면 그때만 상세 조회해서 정확한 시간대를 찾아 알림 | 특정 날짜를 정하지 않고 "아무 때나 취소 나면 다 알려줘" 원할 때 |
| **특정 코트+날짜** | 매번 해당 날짜의 시간대별 상세 페이지를 조회 | 이미 원하는 날짜가 정해져 있어서 그 날만 정밀하게 보고 싶을 때 |

## 🌍 다른 지역 사이트 추가하기

이 앱은 사이트마다 독립된 "프로바이더" 모듈로 구성되어 있어서, 새 지역을 추가할 수 있어요.
다만 지역마다 예약 사이트가 서로 다른 시스템(다른 회사가 만든 사이트)일 가능성이 높아서,
**사이트 구조를 먼저 확인해야** 정확하게 동작하는 스크래퍼를 만들 수 있어요.

### 추가하고 싶은 사이트가 있다면 이렇게 알려주세요

1. 그 사이트의 **월별 캘린더(또는 코트 목록) 페이지**를 브라우저에서 열고,
   Ctrl+S(또는 Cmd+S)로 "웹페이지, 완전함" 형식으로 저장 (html 파일 + `_files` 폴더가 같이 저장됨)
2. 원하는 코트의 **특정 날짜 상세(시간대별 예약현황) 페이지**도 같은 방식으로 저장
3. 두 파일(또는 압축)을 전달

이 정보만 있으면 `providers/_template.js`를 기반으로 그 사이트 전용 스크래퍼를 만들고,
`providers/index.js`에 등록해서 앱의 사이트 선택 드롭다운에 바로 추가할 수 있어요.

### 직접 추가하고 싶다면 (개발 지식이 있는 경우)

`providers/_template.js`를 복사해서 `fetchMonthAvailability`, `fetchDayDetail` 두 함수를
그 사이트 구조에 맞게 구현한 뒤, `providers/index.js`에 `require`해서 배열에 추가하면 됩니다.
서버/스케줄러/프론트엔드는 이미 프로바이더에 상관없이 동작하도록 만들어져 있어서 추가 수정이 필요 없어요.

## 참고 사항

- 시간대는 06:00~22:00, 2시간 단위 8개 슬롯으로 고정되어 있는 걸 확인했어요
  (`providers/gytennis.js`의 `TIME_SLOTS` 참고). 다른 코트가 다른 시간 구조를 쓰면
  그 코트의 상세 페이지를 다시 저장해서 보내주시면 반영해드릴게요.
- `data-kind="R"`(개인 예약)과 `data-kind="B"`(단체 대관)를 모두 "예약됨"으로
  처리하고 있어요.

고양은 매 확인 주기(3분)마다 코트당 기본 1번의 요청(월별 캘린더)이 나가고,
거기에 더해 **가까운 7일(`NEAR_TERM_DAYS`)은 총 개수가 안 늘었어도 매번 상세 조회**를
추가로 합니다 (그래야 "다음 7일 시간표" 화면에 보여줄 데이터가 쌓여요). 그 이후
날짜는 예전처럼 총 개수가 실제로 늘었을 때만 상세 조회해서 가볍게 유지해요.
코트당 대략 1 + 7 = 8번 정도, 10개 코트면 3분마다 80번 안팎의 요청이 나가는 셈이라
여전히 무리한 수준은 아니에요.

## ⚠️ 사이트 요청 부담 줄이기 (도봉/김포처럼 캘린더가 부정확한 사이트)

도봉/김포는 캘린더가 "가능/불가"만 알려주고 정확한 빈자리 개수를 안 줘서, 매 확인
주기마다 **날짜마다 실제로 상세 조회**를 해야 정확하게 취소를 잡아낼 수 있어요.
문제는 이게 코트 수 × 날짜 수만큼 요청이 나간다는 거예요 (예: 김포 8코트 × 한 달
남은 날짜 25일 = 3분마다 200번 넘는 요청).

그래서 이 사이트들은:
- 한 달 전체가 아니라 **가까운 14일까지만** 확인해요 (`.env`의 `DAYS_AHEAD_LIMIT`로 조절 가능)
- 요청 사이마다 0.4초씩 살짝 텀을 둬서 한꺼번에 몰아치지 않게 해요

그래도 여전히 다른 사이트보다는 요청이 많은 편이에요. 더 안전하게 쓰고 싶으면:
- `.env`의 `CHECK_INTERVAL_MIN`을 3분에서 5~10분으로 늘리기
- `DAYS_AHEAD_LIMIT`을 14에서 7 정도로 더 줄이기 (당장 이번 주만 신경쓴다면 충분해요)
- 고양처럼 정확한 사이트도 `NEAR_TERM_DAYS`(기본 7)를 줄이면 요청이 더 줄어요
  (다만 "다음 7일 시간표"에 보여줄 수 있는 날짜 수도 그만큼 줄어들어요)

## 김포시체육회는 어떻게 동작하나요? (⚠️ 베타)

파르코스 테니스장(1~8코트)을 대상으로 합니다. 저장된 페이지에 상태 범례가 명확히
문서화되어 있어서 신뢰도 있게 만들었어요:

- 달력 셀: `of`=휴관, `no`=불가(대부분 "예약 가능 기간 밖"이라는 뜻), `on`=가능, `ok`=선택됨
- 시간대: `no`=불가, `on`=가능 — 같은 체계를 그대로 씁니다

도봉구와 마찬가지로 "달력에 가능/불가만 있고 정확한 개수가 아님"이라서, 매 확인 주기마다
날짜별 상세 시간표를 직접 비교하는 방식으로 동작해요 (`supportsAccurateMonthCount: false`).

⚠️ 범례 자체는 확실하지만, 실제로 "가능(on)"인 시간대가 찍힌 응답으로 직접 검증하진
못했어요 (저장된 페이지의 날짜엔 마침 전부 마감 상태였음). 문제 생기면 알려주세요.

## 📋 변경 이력 로그

조회할 때마다 예약 가능 시간표가 바뀐 내역(새로 열린 시간대 / 다시 마감된 시간대)이
`data/availability-changes.jsonl` 파일에 한 줄씩(JSON Lines) 계속 쌓입니다.

- 앱 화면 아래쪽 "📋 최근 변경 이력" 카드에서 최근 30건을 바로 볼 수 있어요
- `GET /api/change-log?limit=100` — 최신순으로 API로도 조회 가능
- `GET /api/change-log/download` — 로그 파일 전체 다운로드
- 파일이 5MB를 넘으면 오래된 기록부터 자동으로 정리돼요 (최근 5,000줄 유지)

## 🌐 웹으로 배포하기 (Railway 추천)

로컬 PC를 켜두지 않고, 폰 브라우저로 아무 때나 접속해서 "홈 화면에 추가"하면
앱처럼 쓸 수 있어요. Web Push는 **HTTPS 환경에서만** 동작하고,
스케줄러가 계속 돌려면 **서버가 상시 실행 중**이어야 하는데, Railway는 둘 다 무료로 제공해요.

### 1) GitHub에 올리기

```bash
cd tennis-alert
git init
git add .
git commit -m "init"
```

GitHub에서 새 저장소를 만들고, 안내되는 명령어로 push하세요.

### 2) Railway에 배포

1. https://railway.app 가입 (GitHub 계정으로 로그인 가능)
2. "New Project" → "Deploy from GitHub repo" → 방금 만든 저장소 선택
3. "Variables" 탭에서 환경변수 등록:
   - `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`
   - `CHECK_INTERVAL_MIN` = 3
   - `DATA_DIR` = `/data`
4. "Volumes" 탭에서 볼륨 추가 → 마운트 경로를 `/data`로 지정
5. "Settings" → "Networking" → "Generate Domain"으로 HTTPS 주소 생성

### 3) 폰에서 접속

1. 생성된 HTTPS 주소를 폰 브라우저로 접속 → 알림 권한 허용
2. 브라우저 메뉴에서 **"홈 화면에 추가"**

**⚠️ 아이폰(iOS):** Safari로 그냥 열어놓은 상태로는 푸시가 안 되고,
반드시 **"홈 화면에 추가"로 설치한 아이콘으로 실행한 상태**에서만 알림이 동작해요 (iOS 16.4+).

## 🌐 웹으로 배포하기 (Netlify + cron-job.org, 다중 사용자용)

여러 사람이 같이 쓰게 하려면 Netlify + cron-job.org 조합도 가능해요. Railway와 다르게
"항상 켜져있는 서버"가 아니라 **필요할 때만 실행되는 서버리스 함수** 방식이에요.

- **Netlify**: 화면(정적 파일) 호스팅 + API를 서버리스 함수로 실행, 데이터는 Netlify Blobs에 저장
- **cron-job.org**: 예전의 `node-cron` 역할을 대신해서, 주기적으로 함수를 "호출"해주는 외부 서비스

### 1) GitHub에 올리기 (위 Railway 섹션 1번과 동일)

### 2) Netlify에 배포

1. https://netlify.com 가입 → "Add new site" → "Import an existing project" → GitHub 저장소 선택
2. 빌드 설정은 `netlify.toml`에 이미 다 들어있어서 (publish: `public`, functions: `netlify/functions`)
   대부분 기본값 그대로 두면 됩니다.
3. "Site configuration" → "Environment variables"에서 등록:
   - `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`
   - `TICK_SECRET` = 아무 문자열이나 (cron-job.org가 이 값을 알아야 확인 함수를 실행할 수 있음)
   - (`NETLIFY` 환경변수는 Netlify가 자동으로 설정해주므로 직접 등록할 필요 없어요)
4. 배포 완료되면 `https://내사이트이름.netlify.app` 같은 주소가 생겨요.

### 3) cron-job.org로 주기적 확인 예약

Netlify Functions는 실행 시간 제한이 있어서, 등록된 감시 대상을 **한 번 호출에 하나씩만**
순서대로 확인합니다 (라운드로빈). 그래서 cron-job.org는 자주 호출하도록 설정하는 게 좋아요.

1. https://cron-job.org 가입 → "Create cronjob"
2. URL: `https://내사이트이름.netlify.app/tick?key=위에서_설정한_TICK_SECRET`
3. 실행 주기: 1분마다 (무료 플랜에서 지원하는 가장 짧은 주기로 설정 추천)
4. 저장하면 그 순간부터 자동으로 주기적 확인이 시작돼요

감시 대상이 N개면 한 바퀴 도는 데 대략 N분이 걸리는 셈이에요 (감시 대상이 많아지면
cron-job.org 호출 주기를 더 짧게 하거나, `tick.js`가 한 번에 여러 개씩 처리하도록
늘리는 것도 가능해요 — 필요하면 말씀해주세요).

### 4) 폰에서 접속

Railway 섹션의 "3) 폰에서 접속"과 동일합니다.

## 🔧 자주 발생하는 오류

### `unable to verify the first certificate` (SSL 인증서 오류)

윈도우 PC에서 백신 프로그램(알약 등)이나 회사/공유기 네트워크가 HTTPS 트래픽을 검사하면서
자체 보안 인증서를 끼워 넣는 경우 발생해요. 브라우저는 윈도우 인증서 저장소를 신뢰해서
문제없지만, Node.js는 기본적으로 그 저장소를 보지 않아서 막힙니다.

`npm start`가 이제 자동으로 `--use-system-ca` 옵션을 붙여서 실행하도록 해뒀어요
(윈도우 인증서 저장소를 같이 신뢰하게 만드는 옵션). 이미 이 오류를 본 경우:

1. 서버를 껐다가(Ctrl+C) 다시 `npm start`로 실행해보세요.
2. 그래도 같은 오류가 나면 Node.js 버전이 너무 오래된 걸 수 있어요 (`--use-system-ca`는
   Node 22.9 이상에서 지원). `node -v`로 확인 후 필요하면 https://nodejs.org 에서
   최신 LTS로 업데이트하세요.
3. 그래도 안 되면 임시로 `npm run start:no-ssl-check`로 실행할 수 있는데, 이건 인증서
   검증 없이(TLS 검증을 우회) 여전히 오류가 나는 경우를 위한 **최후 수단**이에요 — 이 모드는
   보안상 권장하지 않으니 임시 확인용으로만 쓰세요.
